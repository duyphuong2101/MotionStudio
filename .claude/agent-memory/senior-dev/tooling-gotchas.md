- The Grep tool (ripgrep) silently skips `out/` and `trash/` because they are gitignored. A directory or glob search under `out/` returns "No matches". Pass the exact file path (e.g. `out/<p>/<job>/status.json`) to search inside it.
- `npm test` uses Node's spec reporter. The summary lines are `ℹ tests N`, `ℹ pass N`, `ℹ fail N` (not TAP `# tests`). Filter on those when you capture output. In Git Bash `grep -E "^. (tests|pass|fail) "` matches nothing because `ℹ` is multi-byte; use `grep -E "(tests|pass|fail) [0-9]+$"`.
- `tests/templates.test.mjs` pins sha1 hashes of `build()` output (`PARTS_BASELINE`). Any unconditional text change in `templates/kit.mjs` `page()` breaks them, so add new kit behaviour as text that is only written when an option asks for it (see the `mixed` / `particles` branches).
- A new kind in a slot renumbers `sampleScript` ids (`cta-3` → `cta-4`), so a "page unchanged without the new kind" hash must drop the kind from `sequence` before building, not filter scenes afterwards (see `NO_SHOT_BASELINE`).
- `rm -rf` inside a Monitor command is refused by the permission layer; deleting a scratch job with `node -e "fs.rmSync(<exact path>, { recursive: true, force: true })"` went through.
- On Windows, `writeJson`'s temp + rename can fail once with EPERM in `tests/engine.test.mjs` or `tests/fix-jobs-brief.test.mjs` (a file indexer holding `status.json`). Rerun the file alone before treating it as a regression.
- Monitor commands run in parallel, not in sequence: a `sleep 300` Monitor does not make the next tool call wait. To wait for a long run, start one Monitor whose command blocks until the result file shows the end marker and act on its notification; notifications can arrive late and out of order (2026-10-23).
- 2026-10-29 (timeline editor): a subagent session had neither Bash nor Monitor (ToolSearch found no shell tool). Tests and `node --check` could not run at all; write the tests, check them by reading, and say plainly in the report that nothing ran.
- Some sessions list no Bash tool. `Monitor` with a command that exits runs a one-shot shell command (npm test, `node engine/cli.mjs ...`). Write the output to a file and read it back, because only stdout lines become events. A subagent session on 2026-10-29 had neither Bash, PowerShell nor Monitor (ToolSearch found none): nothing could run, so binary files (PNG fixtures, golden references) had to be made by the test or left to the caller, and the report must say "not run".
- Browser QA of `ui/app.js`: `S` is module-scoped, so `browser_evaluate` cannot read it; read the DOM or `fetch('/api/...')` instead. Playwright `fill` respects `maxlength`, so to test a server limit message set `el.value` from script and dispatch `input`. To test UI logic the real data cannot reach (e.g. format intersection when every mixable template has all six formats), stub `/api/state` with `page.route` in `browser_run_code_unsafe` and `unroute` afterwards.
- QA without touching the user's running server on 4780: `server/server.mjs` already reads `MOTION_STUDIO_PORT`, so `env -u GEMINI_API_KEY ... MOTION_STUDIO_PORT=4791 node server/server.mjs` in a Monitor gives a second instance. TaskStop on that Monitor leaves the node process listening on Windows: kill the PID that `netstat -ano` shows on 4791 only.
- Playwright MCP may only write files under the project root (`.playwright-mcp/`), not the scratchpad. After a reload, wait for `networkidle` before clicking the Brand tab, or boot resets the tab and the panel stays `display:none`.
- `busy(btn, fn)` in `ui/app.js` rewrites the control's `innerHTML`: never pass it a `<select>` (its options vanish).
- Typing the escape ` ` / ` ` in an Edit or Write call lands as the literal character in the file, which breaks a regex literal ("Invalid regular expression: missing /"). Build it with `String.fromCharCode(0x2028)` as `jsonForScript` does; check with Grep `[\x{2028}\x{2029}]`. The same happens to any `\uXXXX` in a Write (2026-10-29: `﻿` and `̀-ͯ` landed as literal characters in `engine/scenescript.mjs`); use `\p{M}` with the `u` flag, or `trim()` (it drops a BOM), and Grep the new file for `\\u[0-9a-f]{4}` to confirm.
- `AbortSignal.timeout` does not hold the event loop open: a test that awaits only a hung fake fetch ends as "Promise resolution is still pending but the event loop has already resolved" and cancels the rest of the file. Hold the loop with a `setTimeout` cleared in `t.after` (see `tests/worker.test.mjs`); `generate.test.mjs` gets away with it through its `settle()` poll.
- A fake `fetch` in tests must build a new `Response` per call: a body can be read once, so a reused instance fails the second call.
- Run through Monitor (stdout redirected to a file), `npm test` prints TAP, not spec: the summary is `# tests N` / `# pass N` / `# fail N`, and nothing reaches the file until a test file finishes.
- An Edit whose `old_string`/`new_string` end in a trailing space can lose that space at the seam (2026-10-22: `&& !` became `&&!` in `engine/brand.mjs`). Read back the joined line after inserting a line before existing code.
- The Grep tool's `glob` with braces over directories (`{explainer,data-story}/template.mjs`) returned no matches although the files match; use `*/template.mjs` or a direct file path.
- Browser QA of a job pane: on load the UI auto-selects a job (e.g. `a1-hook`), so `waitForSelector('#revbox table')` after clicking another job can match the first job's pane. Wait for a selector unique to the target job (a `data-sid` of its scene).
- A scratch job with a script can be seeded without the Director: a scratchpad node script that calls `claim`, writes `source.draft.json` / `script.draft.json`, then `commit(…,'source')` and `commit(…,'script')` from `engine/pipeline.mjs`.
- `cuts.test.mjs` / `motion-blur.test.mjs` e2e cases fail with "Project zz-test-*-e2e already exists" when another session runs the same files at once; the fixtures are gone a minute later. Rerun before calling it a regression.
- Browser QA of a view that needs saved data you must not write (e.g. an NSC sequence): stub `/api/sequences?project=…` with `page.route` and take the screenshot in the same script. Once you unroute, the UI's periodic refresh puts back the real list. A reload with a dirty form opens a `beforeunload` dialog, so register `page.on('dialog')` first.
- `assert.throws(fn, /regex/)` tests the regex against `String(err)` (`"Error: msg"`), so a `^` anchor fails. Use `(e) => e.code === 429 && /^…/.test(e.message)`.
- `fetch_page` resolves each hop with `node:dns/promises` by default (2026-10-23). A worker test that reaches `fetchPage` must inject `lookup` (tools ctx `lookup`, or the `fetchPage` option), or it hits real DNS for `shop.example.com`. `worker-run.test.mjs` flaked once ('done' !== 'paused') while another process ran the suite on the same `zz-test-worker-run` fixture; it passed twice alone.
- Second-port server check: stripping every `keyEnv` from the child env is not enough, `server/keys.mjs` reloads them from the root `.env` at start (2026-10-23: `gemini.hasKey` stayed true). And `DELETE /api/director/pause` on the 4791 instance clears the real `logs/director/pause*.json`; print the GET `pause` field before calling it.
- Review-page QA on the second instance: `MOTION_STUDIO_PORT=4791 MOTION_STUDIO_REVIEW_PORT=4792 node server/server.mjs --review` (without the review port it collides with the person's 4781). The link is printed on the LAN IP with a fresh `?code=`. Panel-state QA: stub `/api/director**` (GET serves a mutable state object, every non-GET is recorded and faked) plus `/api/jobs?project=*` (mark jobs `queued`) so the run button shows without writing anything.
- On Windows, `spawn('git', …, { cwd: <untrusted folder> })` lets libuv pick a `git.exe` from that cwd before PATH. Keep `cwd: ROOT` and pass the folder as `git -C <dir>` (see `engine/evidence.mjs` `git()`, 2026-10-23).
- Every test that spawns `server/server.mjs` runs its startup recovery (`recoverStale`, `recoverInflight`) against the shared real `out/` and `logs/`. `recoverInflight` keeps one file per server pid (`logs/inflight/<pid>.json`) and skips a live server's file, so a test server never kills the person's prepare; `recoverStale` (API-worker jobs by actor) has no such guard (2026-10-23).
- `fetch_page` swaps the platform `fetch` for `pinnedFetch` (node:https with a fixed `lookup`); an injected stub is used as given. Tests that replace `globalThis.fetch` after the imports keep using their stub; a test that leaves the real fetch in the ctx would now open a real socket.
- PowerShell from `spawnSync` (no shell): quote a WQL `-Filter` with single quotes; embedded `"` in an argv item is fragile.
- A test that must not spawn `claude.exe` on the seat path: give the server child an empty temp dir as `PATH`, `USERPROFILE` and `HOME`, so `resolveClaude` finds neither PATH nor the VS Code extension copy (503 "Claude Code was not found").
- `ui/app.js` reads `document` at import, so node tests cannot import it. Pure UI helpers go in `ui/shots.js` (no DOM; tested by `tests/fix-ui-helpers.test.mjs`). In-flight actions use `guarded(key, btn, fn)` + `applyLocks()` after each re-render, not bare `busy()`. Some sessions have no Bash: run `node --check` and `node --test` through Monitor and write output to a scratchpad file (2026-10-23).
- In a kit page the renderer's `js` runs before `let afterSeek = null;`, so assigning `afterSeek` at its top level throws "Cannot access 'afterSeek' before initialization" (page never ready). Assign it inside a `KINDS` builder, which runs in `build()` (2026-10-23).
- Pinned explainer hashes (`PARTS_BASELINE`, `NO_FLASH_BASELINE`, `NO_MODEL_BASELINE`) include the kit's clip-seek js because the sample has a video scene. To prove a hash move comes from one change only, regex-swap the old text back into `build()` output in a scratch script and compare with the pinned sha.

**Why:** in 2026-10 (sequences feature) a Grep for `"status": "done"` under out/ found nothing although 6 jobs were done, and the first test-summary filter matched nothing. In 2026-10-15 (Gemini panel) the second-instance and Playwright items cost several retries.

**How to apply:** before deciding "no done jobs" or "tests printed nothing", re-check with exact paths or the spec-reporter patterns. See also [[layout-verification-gotchas]].
