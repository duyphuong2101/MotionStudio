## Intent
After building the NSC award film, the user asked to automate the parts that were done by hand (footage prep, play-through QA, review sheets) and to remove the remaining friction (film-level duration budget, loudness match, real voice, SFX, evidence import). Done one epic at a time, top to bottom.
**For whom / outcome:** the person producing a multi-part brand film in Motion Studio: fewer manual ffmpeg steps, problems caught before render, and far fewer Claude tokens per film (no ad-hoc scripts or screenshot review).

## Options considered
| Option | Pros | Cons | Chosen? |
|--------|------|------|---------|
| One big "editor" rewrite | Coherent UX | Huge risk, nothing ships for days | ❌ |
| Eight small epics on the existing engine/UI, each opt-in and tested | Each ships alone; old outputs unchanged | Some UI spread across tabs | ✅ |
| Keep doing these steps by hand with Claude | No code | Costly per film (this session: ~248M cached tokens) | ❌ |

## Floor (applies to every epic)
- No model calls anywhere new. STT stays the local whisper path already used by `transcribe`.
- Every ffmpeg/git child process: argument arrays, `shell:false`, timeout, capped log (`runEngine` / `ffmpeg()` helpers).
- Outside ids and file names → `assertId` / `assertFileName` + `within()`. New routes keep the 127.0.0.1 + Host/Origin/`X-Studio` checks. The review link (`server/review.mjs`) stays GET-only: new write routes are never added to `reviewRoute`.
- No new npm dependencies. English for every label, message and error.
- Standard outputs stay byte-identical unless an epic says otherwise (golden hashes in `tests/templates.test.mjs`).

## Epics (in order)

### E1 — Footage import and shot finder
- Engine `engine/footage.mjs`: analyse a video asset → shots (ffmpeg scene detection), one thumbnail per shot, duration/fps/size/audio, letterbox bars (black and white), stored under `out/_footage/<project>/<asset>/` (`shots.json`, `thumbs/*.jpg`). Re-uses `probeMedia`, the `ffmpeg()` helper, `transcribeAsset`/`loadTranscript` for searchable words.
- Clip maker: `makeClip(project, asset, opts)` → a new brand asset plus a sidecar `<name>.clip.json` (source asset, in/out, operations) for provenance. Options: in/out; crop rect or percentage band (drop burned-in captions); `fill`: `cover` | `blur-fill` (vertical → 16:9 over a blurred copy); `blurRegions` (rects, feathered) and an optional `keep` ellipse (subject stays sharp); `gainDb`; `mute`. Output 1920×1080 (or the requested size), 30 fps, H.264, AAC 48 kHz.
- CLI: `node engine/cli.mjs shots <p> <asset>`, `node engine/cli.mjs find <p> <asset> "<words>"` (transcript search → times), `node engine/cli.mjs clip <p> <asset> --in --out [--crop-bottom 12] [--fill blur-fill] [--gain -4.5] --name <new>`.
- Server: analyse (runs the engine child), shots JSON + thumbs (GET), make-clip (POST). Brand tab: a "Shots" panel per video asset (thumbnail strip with times, transcript search, in/out, preset, one preview frame, "Make clip").
- Verify: unit tests for option validation and filter graphs; one real ffmpeg test on a generated clip (scene cut detected, blur-fill output 1920×1080, sidecar written); route tests (traversal refused, review link has no make-clip).

### E2 — Play-through QA in prepare
- `engine/playcheck.mjs`: plays the composition forward frame by frame (configurable step, default 1/12 s per the E2 brief, capped frames) and reports: text over text (using text-node client rects, not element boxes, so a 300 px number's line box is not a false hit), a caption box covering scene text, more than one caption line or scene at once, state that differs from a direct seek (every 0.5 s), lint findings mid-motion.
- Runs in prepare after the stills; findings go into `lint` (errors block like today). Config switch and budget in `config/studio.json`.
- Verify: tests that build pages with a known overlap / stacked scenes / history bug and assert each finding; existing templates' samples pass clean.

### E3 — Review sheet and pacing table
- At prepare: `review/sheet.jpg` (three frames per scene: in, middle, before cut) and `review/pacing.json` (per scene: length, words, words per second, head, tail, silence share). CLI `node engine/cli.mjs review <p> <j>` prints the table and the sheet path.
- UI Preview tab: the sheet and the pacing table (flags: >3.2 wps, tail >1.5 s, silence >25%).
- Verify: prepare on a sample job writes both; UI shows them (Playwright).

### E4 — The film: budget across parts, drafts, template change
- Sequences gain an optional `targetDuration`; a draft sequence may list parts that are not rendered yet (render still needs every part done). The sequence page shows each part's prepared length against the budget and the total.
- New sequences default `musicBed: true`.
- A job whose script exists can change template/mix: the old script is kept as `script.prev.json`, the job goes back to the director (dirty from step 3) instead of forcing a duplicate brief.
- Verify: engine tests for draft sequences, budget maths, template change with locks kept where fields still exist.

### E5 — Loudness match for clip sound
- In prepare, each clip that plays its own sound is measured (speech loudness, `ebur128`/`volumedetect` on the voiced span) against the voice-over; its gain is set so both sit within ±1 dB. Recorded in timing.
- Verify: test with two generated tones at different levels → matched within 1 dB.

### E6 — Recorded voice
- A job may use one recorded take (brief field `voiceTake`: an audio asset). Prepare transcribes it locally, aligns its words to the script's voice lines (sequence alignment, tolerant to small slips), cuts it per scene, and uses those cuts instead of TTS; captions use the script text with the recorded timings. Low alignment confidence → a clear error naming the scene.
- Verify: test with a generated TTS take of the script as the "recording": alignment maps every scene; a take with a missing line fails with that scene named.

### E7 — Cut SFX
- A small generated SFX library (deterministic ffmpeg synthesis: whoosh, hit, riser, soft click) like the music library. Brand `sfx: { cut: "whoosh"|"hit"|"none", gainDb }`; a scene may override with `sfx`. Mixed at scene cuts in the final mix and kept by the sequence music bed.
- Verify: mix-filter tests; a real render of a sample job has the SFX at the cut times.

### E8 — Evidence import
- `node engine/cli.mjs evidence git <repo> --since <date> [--grep <pattern>]`: read-only git (log, branch --contains) → fact lines with release-branch provenance. Repos must be listed in `config/studio.json` → `evidence.repos`.
- A CSV importer (e.g. a GA4 export) → period totals and growth as fact lines, with the file and range named. No credentials, no network.
- Verify: tests on a temporary git repo and a sample CSV.

## Out of scope
- Any model call, GA4/API access with credentials, PDF parsing (needs a dependency), changes to the review link's read-only rule.
