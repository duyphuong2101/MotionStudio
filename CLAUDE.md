# Motion Studio

Brief-to-video tool. A director (Claude Code on a company seat) writes `source.json` and `script.json`; a deterministic engine turns them into an HTML + GSAP composition, stills, and an MP4. A person approves the storyboard in a local UI before anything is rendered.

## Commands

- `npm install` once (Node 22.23.4+, 24.22.1+ or 26.12.1+, the releases with the October 2026 security fixes, `NODE_FLOOR` in `engine/runtime.mjs`: older ones get a warning and no review link; Chrome installed; ffmpeg comes from `ffmpeg-static`).
- `npm run ui` starts the UI on http://127.0.0.1:4780. `npm run ui:review` also prints a read-only review link (`http://<LAN IP>:4781/?code=…`) for people on the same network.
- `/studio run` (this repo's skill) processes queued briefs. `/studio status` lists jobs. The same command works in Cursor (`.cursor/commands/studio.md`), GitHub Copilot (`.github/prompts/studio.prompt.md`) and Google Antigravity (`.agents/workflows/studio.md`), each on its own copy of the one skill (`.cursor/skills/studio/`, `.agents/skills/studio/`, written by `node .ai/scripts/sync-director-prompt.js` from `.claude/skills/studio/SKILL.md`; edit only that). Those agents have no seat allowlist: the skill holds them to the Director's commands, and Copilot (`.vscode/settings.json` → `chat.tools.terminal.autoApprove`) and Cursor (`.cursor/hooks/ask-before-render.js`) ask the person before `approve`, `render` or `sequence`. Antigravity's always-on rule is `.agents/rules/motion-studio.md`. Every other skill and Cursor rule reaches Codex, Antigravity and Copilot CLI through `.agents/`, written by `node .ai/scripts/sync-agent-hosts.js` (run by `generate-mirrors.js`; never edit by hand).
- `node engine/cli.mjs help` lists engine commands. `npm test` runs unit tests.
- `node engine/cli.mjs import-remotion <project> <dir> [--job] [--template] [--composition]` (`engine/remotion.mjs`, a person's tool, not in the Director's allowlist) reads a Remotion project's `.ts/.tsx/.js/.jsx/.json` files as text and runs nothing: it writes a queued brief (format from the composition size, length in the template's range, facts that name their file, the scenes with their seconds in the notes) and saves the `public/` files it references through `saveAsset`; it skips links, `node_modules`, `..` paths and remote files and caps files, bytes and texts.
- `node engine/cli.mjs import-script <project> <file.txt> [--job] [--by]` and the UI's New from script (`POST /api/projects/<p>/scene-script`, `engine/scenescript.mjs`, plan `.ai/plans/scene-script.md` part A; a person's tool, not in the Director's allowlist, no model) turn a scene script (`SCENE n — TITLE (a–b seconds)` blocks with `CLIP: name.mp4 0:00-0:04`, `IMAGES:`, `VOICE:`, `ON SCREEN:`) and the brand assets it names into a scripted explainer job: clip scenes are `video` scenes with `sound: true` (cut at `out` or held with `hold` to fill the span; a silent clip cannot hold its span), IMAGES a `lifestyle.gallery` through the mix, the TITLE a title card and `End card:` a `cta`, both needing a VOICE line (the cta a BUTTON too); every field locked as the person's own, `generated: "scene-script"`, the descriptions kept in `scene-script.json`. A script with no TITLE and no End card (a prompt-style episode script: `Cảnh n – Title`, `an 8-second video` in its text, `ACTION:`/`CAMERA:` sections as notes) becomes a `clip-reel` job instead (`templates/clip-reel`, `extends` explainer, 1-12 `video` scenes full frame with their own sound, `captions: false`, no cards; ON SCREEN gives a clip a lower third; the Director never writes one).
- Golden frames: `tests/golden.test.mjs` compares every template's sample in 16:9 and 9:16 (3 frames, 480 px grey) with `tests/golden/` by ffmpeg `ssim` (`THRESHOLD` in `tests/golden.mjs`, 0.99; two runs give 1.0000). After a deliberate visual change, `node tests/golden.mjs --update [template...]` rewrites the references; look at them before committing. The references are Windows (Arial) frames.

## Layout

- `briefs/<project>/<job>.json` input written by the UI. Changing the template or mix after a script exists moves `script.json` to `script.prev.json` and sends the job back to the Director from step 3 (source kept). An optional `voiceTake` (a .wav/.mp3/.m4a asset, one recorded take of every voice line in order) replaces TTS: prepare transcribes it locally, aligns it to the scenes (`engine/voicetake.mjs`, `config/studio.json` → `voiceTake`), cuts it per scene and keeps the script's words as captions (brand `voice.cleanup: true` runs each cut through a highpass, FFT denoise, de-esser and compressor first, `takeFilter` in `engine/voicetake.mjs`); a scene the take does not match fails prepare by name.
- `sequences/<project>/<id>.json` a sequence written by the UI: 2-12 jobs of one format (a draft may list unrendered parts; preview and render need every part done; optional `targetDuration`, and `sequenceBudget` sets each part's length against it), joined by ffmpeg (`node engine/cli.mjs sequence`) into `out/<project>/<id>/<title or id> v<N>.mp4`, a new version per render (`status.outputs.final` names the latest; older versions and a pre-version `final.mp4` stay). No model involved. A sequence id cannot be a job id in the same project. `pad: { head, tail }` (0-5 s each, `PAD_MAX`) puts silent black before the first part and after the last, the picture fading in and out over 0.8 s and the music bed kept off it, so a player can switch in and out cleanly. `musicBed: true` replaces the parts' own music with one brand track under the whole film (each part's `voice.wav`/`footage.wav` placed at its offset, ducked, looped by crossfade when the track is shorter).
- `profiles/<project>/brand.json`, `voice.md`, `assets/`, `icons.json`, `transcripts/<asset>.json` one folder per brand. `icons.json` holds the brand's uploaded icons as motion-kit paths (`engine/icons.mjs` turns an SVG into one M/L/C/Z path in the 100x112 box); templates get them as `icons` in the build args. Optional brand fields read by `templates/kit.mjs`: `fonts.files` (licensed font assets loaded with `@font-face`), `fonts.headingWeight` (100-900: one weight for every heavy class of the kit and its templates, `HEAVY_CLASSES` in `templates/kit.mjs`, for a guide that allows only Semibold headings), `subtitles` (one subtitle look for every template: a preset `style` — `classic`, `highlighter`, `minimal`, `pill` (a marker pill slides from word to word) or `pop` (words pop in as spoken), a few words at a time in Roboto/Montserrat/Inter, sized for a phone, in a band clear of player controls and a portrait icon rail, which also raises `contentArea` — or a custom box, e.g. black on a white box), `logoBug` (the logo fixed top-left, `logoDark` on dark scenes), `safeArea` (3-12, percent of the frame: the logo bug and the subtitles keep that far from the edge, `safeAreaCss` in `templates/kit.mjs`, for a broadcast safe zone), `shine` (a light band sweeps across each `.btn` once it is in), `confetti` (a burst of brand-coloured pieces flies from each `.btn` as it lands, GSAP Physics2D), `reveal` (`chars` or `lines`: headings split by GSAP SplitText, on the profiles with the plain entrance, `revealable` in `templates/kit.mjs`), `ease` (`snappy`, `soft`, `spring` or a CustomEase path from `M0,0` to `1,1`: the page's default ease `X`, `EASES` in `engine/brand.mjs`; the kit writes SplitText, CustomEase and Physics2D into a page only when its brand asks, `GSAP_FILES` in `engine/vendor.mjs` copies them into every job), `leaks` (a warm glow and one in the accent flare across the frame at every cut), `carry` (cinematic and clean only, the profiles with `carrier`: an accent bar under each scene's `[data-anchor]`, kicker or heading glides to the next scene's at every cut, `CARRY_JS` in `templates/kit.mjs`), `backdrop` (`mesh`, `aurora`, `flow` or `shapes`: a WebGL layer in the brand colours behind every scene, replacing the particles; `shapes` is lit 3D solids drifting near the frame edge) and `wipe` over every cut (`liquid`: a WebGL band in primary with accent edges sweeps across, its edges smeared by their own speed; `iris`, `burn`, `glitch` and `flash` (through white) follow HyperFrames' shader transitions, redrawn as brand-colour layers because a page cannot sample its own scenes, each with its own window, `WIPE_WINDOW`; both in `templates/gl.mjs`), `blend` (`whip`, `zoom`, `warp` or `split`, `BLENDS` in `engine/brand.mjs`, `templates/blend.mjs`: both scenes show over 0.25 s either side of every cut (`cutWindows`), each scene group in a `.blw` wrapper mixed with CSS transforms, opacity and SVG filters set from `seek(t)` by `drawBlend`; it replaces the profile's cut, panel and veil (the cinematic push stays), deliberately breaks the one-scene-at-a-time rule, never on an overlay or a one-scene page; a brand sets a wipe or a blend, not both, and a look's wipe gives way to the brand's blend; the play-through check skips its windows, `__studio.blends`) and `motion`, one row of `MOTION_PROFILES` in `engine/brand.mjs` that the kit, the templates and prepare read through `motionProfile(brand)` (never the name; the Brand tab lists `MOTION_OPTIONS` from `ui/shots.js`, kept in step by a test): `standard` (absent), `clean` (the cinematic layout and tight gaps with short sharp entrances, 0.15 s fades, no blur, push-in, grain or particles), `editorial` (heading words rise out of a mask, other things wipe in, a brand panel sweeps over every cut unless a brand `wipe` is set), `kinetic` (overshooting entrances, zoom and slide cuts, the standard layout, tight gaps), `parallax` (a drifting camera, text and pictures drifting at their own speed; ui-story keeps its app window still), each with one-line lit captions, and `motion: "cinematic"` (kit helpers bring things into focus word by word on an expo ease, every scene pushes in slowly, cuts are focus pulls, film grain and a vignette replace the particles (brand `film: false` drops both, for a clean frame); the explainer puts footage full-frame under a lower third; content blocks centre between the logo and the subtitles; prepare uses tight voice gaps, `config/studio.json` → `timing.tight`; cuts are blur cuts, never two scenes at once (a cut between two background colours, or to or from a full-frame picture, turns through a veil in the new scene's colour, `VEIL_JS` in `templates/kit.mjs`); captions show one balanced line at a time (`captionLines`), each word turning solid with the brand marker as it is spoken). Scenes may set `theme` (`light`/`dark`/`accent`) on the kinds that list it, and the explainer has a `flash` kind (kinetic one-item-at-a-time type, items up to 40 characters; an item flashes on the word that starts it when the voice says that word, else the beats spread over the line); a flash may set `video` (with `in`/`out`): the clip plays full frame behind the words (whole picture, letterboxed if need be), blurred and shaded, muted. Data-story `stat`, `line` and `bars` take `tone: "up" | "down"` (counted numbers green or red, a lighter green on dark), and `bars` takes `series` (two names) with `value2` on every item for two bars per row under a legend, and `layout: "columns"` for upright bars with the value above and the label below (columns may set `ref`, e.g. `{ "value": 100, "label": "Green zone" }`: one dashed green line across the columns at that value). A ui-story `shot` may set `cue` (one word of its scene's voice line): it starts 0.3 s before that word is said, shots stay at least 1.2 s apart, and pages without a cue are unchanged; a ui-story `shot` scene may set `tilt` (`left`/`right`: the app window swings in turned in 3D depth, then turns slowly toward flat while the voice runs; the next scene is flat again); a ui-story `title` may set `logo: false` to keep the brand logo off that card. A toned bars value colours its unit too, and a bars item may set its own `tone` (that value only, e.g. the faster time in green). A logo-reveal may set `notes` (1-6 silent small lines, 90 characters each, one item a line, e.g. end notes listing the AI tools used): the reveal plays as usual, then once the voice is done the logo lifts, the caption goes and the notes roll up from below the frame like film credits, each line fading in once inside the safe area, and settle under the logo; with `pace: focus` the sting holds about 6 s after the voice. `notesCue` (a word of the voice line, with notes) has the voice read the notes: the roll starts on that word and lasts until the voice ends, the captions step aside, and the line may run to 34 words (`data.reveal.voWithNotes`). Lifestyle has a mixable `gallery` kind (2-4 `photos` as instant prints dropped in with the voice, `beats.data.gallery`); a talking-head `clip` may set `layout: split` (speaker to one half, `image` in the other) or `pip` (`image` full frame, speaker in a corner). Text marks (`engine/marks.mjs`): a template with `marks: true` in beats.json (every kit renderer) takes `[[circle:40%]]`, `[[underline:…]]`, `[[strike:…]]` or `[[mark:…]]` in `title`, `subtitle`, `text`, `tagline` or `quote` (at most 2 per field, never in a voice line; limits count the words without the brackets); the kit draws each when the voice says its first word, and the Director gets the rule as `marksRule` in its context. `voice.say` (one word as written → what the voice says, e.g. `"AMAD": "Eh Em Eh Dee"`, `".NET": "dot net"`; `spokenLine` in `engine/tts.mjs` changes only the TTS text, captions and word timing keep the script's words; the Brand tab's "Say as" box) fixes a word the voice reads wrong; check a spelling with `toPhonemes` in `engine/tts/kokoro.mjs` (a lone "A" reads as "uh"). `voice.cast` (up to 4 named extra voices, e.g. `{ "numbers": "am_michael" }`) lets a scene of any template set `speaker` to one of them (`speakScript` in `engine/tts.mjs`; every other scene keeps `voice.voice`; an unknown speaker fails prepare by scene id; a recorded take ignores it). A scene may also set `stress` (1-3 runs of words of its own voice line, checked by `stressAt` in `engine/script.mjs`): the voice says them `STRESS_DB` (4 dB) louder with short ramps (`stressSpans`/`stressFilter` in `engine/tts.mjs`; a limiter guards voice.wav only when a line has stress). Kokoro has no pitch or SSML control, so loudness and punctuation are the only emphasis it takes. Built-in music (`engine/library.mjs` `MUSIC`): `calm-pad`, `soft-pulse`, `steady-tech` and `bright-drive` (upbeat, major key, 120 BPM). `music.duck` (read by `engine/pipeline.mjs` `mixFilter`) dips the music under speech with `sidechaincompress` in the final mix; off by default. `sfx: { cut: "whoosh" | "hit" | "riser" | "click" | "none", gainDb: -30..0 }` (`engine/sfx.mjs`, sounds synthesised once into `library/sfx/` by `engine/library.mjs`) plays a cut sound at every scene start but the first; a scene of the templates that list `sfx` may pick its own (`none` silences that cut). Prepare writes `sfx.wav`; the final mix and a sequence music bed add it after the duck (it never dips the music); absent = no sound, and the mix is unchanged. Brand `grade` (`{ look }` from `GRADES` in `engine/grade.mjs`: `warm`, `cool`, `teal-orange`, `mono`, `faded`, `vivid`, or `{ lut }`, a `.cube` asset checked by `isCube`; optional `amount` 0.1-1; the Brand tab's Colour grade, plan `.ai/plans/art-direction.md` E1): prepare grades every clip in `cutClips` (RGB filters between explicit BT.709 conversions, `videoGradeVf`) and every scene picture it copies (`imageGradeArgs`, alpha kept); brand assets, ui-story `shots`, SVG and the page's own drawing keep their true colours; absent = files copied byte for byte. Per-scene direction (`engine/direction.mjs`, E2 of the same plan; every scene of every template, the Script tab's Direction row, the Director's `directionRule`): `cut` (the scene's entrance: `whip`, `zoom`, `warp`, `split`, `fade` or `cut`; once any scene sets one, `cutPlan` in `templates/blend.mjs` runs every cut of the page through the blend machinery, a cut without its own taking the brand blend, else the brand wipe (drawn only over those cuts), else a crossfade, so the profile's veil or panel no longer draws on that page), `camera` (a move preset from `CAMERA_MOVES` or `{ from?, to }` framings of zoom 1-1.6 and a focus point x/y 0-1, over the largest `img`/`video` covering 30 % of the frame, set from `seek(t)` by `drawCam` through the CSS `scale`/`translate` properties so it composes with the renderer's own transforms; `templates/camera.mjs`) and `grade` (`none` or a preset: prepare grades that scene's clip and writes its pictures as `g-<grade>-<name>` copies the page reads, `pictureCopies`). A page with none of them is unchanged. Music-led rhythm (E3): `analyseMusic` in `engine/beats.mjs` gives the brand track's beat grid and its drops (`findDrops`: the loudness of the next 3 s at least 5 dB over the 3 s before and at the track's median or above, on the nearest beat, up to 3, 8 s apart); a brief's `beatPulse` (the brief form's "Pulse on the beat") writes `timing.pulse` (`pulseTimes`: beats at least 0.9 s apart, the drops as hits) and the kit's `drawPulse` (`templates/pulse.mjs`) swells every scene group through the CSS `scale` property on a cosine rise and fall that peaks on the beat (never a one-frame jump), more with a soft white flash (`#pulsefx`) on a hit; a scene whose picture or clip covers 30 % of the frame takes only the hits (`PULSE_PICTURE`); a scene's `drop: true` (one per script, the Direction row's "The music's drop lands here") moves the music so a drop lands on that scene's start (`dropShift`: from later in the track, or up to 3 s late; `timing.music.shift`, read by `finalMixArgs` as an input seek, a seek inside the loop's first copy, or a late start, and by the preview's sound sync); with cut on the beat, cuts are timed again on the moved grid and the drop wins over a beat. Subject cut-out (E5): a scene's `cutout: true` (the Direction row's "Subject in front of the text"; its picture is `image`, else `asset`, else the first photo, `cutoutPicture`) has prepare run a local segmentation model (`engine/matte.mjs`, `config/studio.json` → `matte`: a U²-Net family ONNX file the person saves as `models/matte/matte.onnx`, never downloaded by the tool; input [1,3,S,S] ImageNet-normalised, first output the subject map, stretched min to max) and write `assets/cut-<scene>.png` (the job's graded picture with the matte as alpha, ffmpeg `scale2ref` + `alphamerge`); without the model the scene renders as before and prepare warns. The kit (`templates/cutout.mjs`) adds the cut-out after every scene's tweens and `drawCutout` lays it each seek exactly over the scene's main picture box (its tweens, a camera, a pulse or a blend included) above the scene's text. Export for an editor (E6): `node engine/cli.mjs export <project> <job>` or the done banner's "Export for editor" (`POST /jobs/:p/:j/run` with `action: export`, only on a done job, the status stays done; a failure lands in `exportError`) writes `out/<project>/<job>/export/`: `scenes/NN-<id>.mp4` (frame exact, silent, cut from `video.mp4`), `stems/` (voice, footage, sfx and `music.wav` as the mix places it but not loudness-normalised, `musicStemArgs`), `captions.srt` and `timeline.xml` (FCP 7 XML for Premiere Pro and DaVinci Resolve, `timelineXml`); a new prepare deletes it. Not in the Director's allowlist.
- `templates/<id>/beats.json` (rules the director must follow) + `template.mjs` (HTML generator). All 20 templates are built in; there is no custom-template editor. `type-film` (plan `.ai/plans/art-direction.md` E4) is kinetic typography: each `line` scene shows its own voice line word for word as large type, every word landing at its time in `timing.words` (TTS, cloud voice or a recorded take), `style` `punch`, `stack` or `build`, up to 3 `accent` words; the page draws no subtitles. A template without `template.mjs` reuses another renderer through `extends`.
- Quick mode (`engine/quick.mjs`, plan `.ai/plans/quick-video.md`): a brief with `quick: true` (only on a template whose `beats.json` has a `quick` block: explainer, product-demo, social-teaser; never with a mix) gets a small quick context from `cli context`. The Director writes `outline.draft.json` (mood, headline, points with their source, cta) and runs `node engine/cli.mjs commit <project> <job> outline`. The engine validates the outline (an over-limit field is an error naming the cut; words are never rewritten), expands it over `beats.quick` (ids `open`/`point-N`/`close`, icons, theme or decor cycle, a stat for a point with a number, `look` from the mood), runs the mechanical repairs every script commit gets (`engine/repair.mjs`: icon, enum, over-max scenes, ids; reported in the result and the history), merges locks and writes `outline.json` + `script.json` (`generated: "outline"`). Looks (`engine/looks.mjs` `LOOKS`: `calm`, `energetic`, `premium`, `bold`) are `script.look`, laid under the brand at prepare and render (brand fields a person set win), chosen in the Script tab's Look select. The quick rules live in `server/worker/director-quick.md` (synced into the studio skill); the full-script path stays for every brief.
- `templates/kit.mjs` is the shared page shell (tokens, subtitles, seek contract) for the newer renderers. `beats.audio: "footage"` makes prepare cut clips into `clips/` and mix their sound as `footage.wav` (`beats.footage: "audio"` takes sound files too; `beats.levels` adds per-frame loudness). A motion scene with a `video` field gets a clip the kit seeks with the page clock (with `sound: true` the clip sets the scene length; `hold: 0-3` keeps its last frame that long after it ends); a render shows that clip (and every `clips/<clip>.mp4` `<video>`, talking-head too) as frames ffmpeg cut ahead into `frames/` (`cutClipFrames` and `CLIP_FRAMES_JS` in `engine/frames.mjs`, injected by `openComposition` at render time; the page file is never changed). Every encode is BT.709 (`BT709_VF` for screenshots and lavfi colour, `BT709_TAGS` on outputs, `engine/media.mjs`). `node engine/cli.mjs bench <project> <job>` times render Chrome counts for `render.concurrency`. The explainer's `model` kind (mixable) shows a `.glb` asset (glTF 2.0 binary, checked on upload) turning (`spin`: `turn`/`orbit`/`hero`/`reveal`/`detail`) with three.js in studio light (`env: "studio"`, a PMREM of three's `RoomEnvironment` built once per canvas; `none` for plain lamps) over a soft contact shadow on a clear ground (`shadow: false` drops it), from an optional start pose `view: { azimuth, elevation, zoom }` (ranges in `VIEW_RANGE`, the same as explainer `data.model.view`) (`templates/model3d.mjs`; prepare copies three flat into `vendor/` with `engine/vendor.mjs`; the Templates tab uses the torus from `engine/glb.mjs`). `node engine/cli.mjs pack-glb <project> --front <pack.png> [--back <back.png>] [--name x.glb] [--depth 0.05-1] [--finish matte|satin|gloss]` (satin is the default and the look before the choice; gloss adds a clear lacquer coat, `KHR_materials_clearcoat`, `FINISHES` in `engine/pack-glb.mjs`) (`engine/pack-glb.mjs`) builds a `.glb` of a product pack from its pictures as a soft pillow (a superellipsoid: rounded corners and edges, faces that bulge a little; margins trimmed by ffmpeg cropdetect, the front picture on the front and stretched round the rim, the back picture on the back) and saves it as a brand asset, so a model scene needs no 3D tool. A model scene may set `path` (2-4 poses shaped like `view`: the camera glides pose to pose on a smooth step, the spin still turns the model) and `explode` (1-6 node names of the .glb pulled out from the centre a third of the way in, `gap` 0.1-1 of the model's size; a pack-glb model has `front`, `back`, `rim`). `product-tour` (`templates/product-tour`, `tourCanvas` in `templates/model3d.mjs`) keeps one model on screen for the whole video: a title over the model rising in, 1-8 `step` scenes each with its own `view`, `explode` and `gap`, the camera gliding from step to step with no cut, then a cta; its title may set `env` and `decal` for the whole tour. Every model scene (and the tour title) takes `env: "brand"` (the studio room built from panels in the brand primary and secondary, so reflections carry the brand) and `decal: { icon, at: [x, y], size, part }` (a brand or built-in icon drawn once on a canvas texture, stamped on the model's front face, riding on `part` so it explodes with it), and may set `bloom` (0-1: the brightest highlights glow, three's UnrealBloomPass with the two widest blur levels off so no haze reaches the canvas edge) and `focus: true` (a shallow depth of field on the model's centre, BokehPass; `copyThree` vendors the passes and drops BokehShader's alpha = 1 line so the canvas stays clear). Both draw through one composer only on a canvas that asks (`data-bloom`, `data-focus`); on SwiftShader they cost about 3.5x (bloom) and 5x (focus) a plain model frame, so keep them for a hero scene. The limits of these fields live in `engine/model-rules.mjs` (shared by the script check, the renderer and `data.model` in beats.json). The explainer's `anim` kind (mixable) plays a Lottie animation: a `.json` export (After Effects Bodymovin or LottieFiles) uploaded as a brand asset (`isLottie` in `engine/lottie.mjs` checks `v`, `fr`, `op` and `layers` on upload), named by the scene's `lottie` field, drawn by lottie-web's SVG player vendored into `vendor/lottie.min.js` (`copyLottie` in `engine/vendor.mjs`) and seeked with the page clock by `goToAndStop` (`templates/lottie.mjs`; `loop: false` holds the last frame, `fit: cover` fills the window); the kit writes the player and its seek hook only into a page that holds one. Every WebGL canvas carries `data-gl`, and `openComposition` opens such a page on SwiftShader so a render gives the same pixels on every machine; every other page opens as before. `beats.alpha` renders a ProRes 4444 `.mov` with transparency.
- `motion-kit/icons.mjs` SVG paths every template can morph between: 11 hand-drawn icons plus about 70 commerce icons generated from Phosphor (`icon-list.json` → `node motion-kit/build-icons.mjs <phosphor dir>` → `icons-set.mjs`; never edit the generated file).
- `engine/` pipeline, CLI, validation, locks. `server/` local UI server. `ui/` static UI.
- Assistant panel (`server/assistant.mjs`, `ui/assistant.js`, the header's Assistant button, plan `.ai/plans/assistant-chat.md`): a chat that makes things from one typed line with no model. `parseAsk` matches a slash command (`/brief`, `/status`, `/director`, `/sequence`, `/clip`, `/brand`, `/help`) or a plain sentence ("new explainer 9:16 about …", "set motion to cinematic", "cut a clip from talk.mp4 0:04-0:12") to one intent; `/status` and `/help` answer from the files; every write comes back as a proposal (`POST /api/assistant/ask`) the person approves or cancels in the panel (`/api/assistant/approvals/<id>/approve|reject`, in memory, `config/studio.json` → `assistant.approvalMinutes` and `maxOpen`), and only then runs through the same functions the buttons use (`saveBrief`, `startDirector`, `createSequence`, `makeClip`, the brand write; `BRAND_FIELDS` lists the brand fields it may change). It never renders, approves a storyboard or deletes, and is not on the review link. ## Rules for using Claude here

- The seat is company-owned. Claude Code runs only when a person starts it: typed `/studio run`, or the UI's Run Director button. Run Director (`server/director.mjs`) has two backends, chosen once per click: the Claude seat (`claude.exe -p` on this machine's own login, no token read, no API key added, the allowlist in `config/studio.json` → `director` with only the person's own user settings loaded (`--setting-sources user`, no project MCP servers), Edit limited to the job's three draft files and no reading of secret files; the default) and the API worker (`server/worker/`, a tool-calling loop over one provider's HTTP API with Node `fetch` and the person's own key from the `keyEnv` variable, used only when `config/providers.json` → `default` names a provider with an adapter, a model and a key). Both run one at a time (also across UI servers on this machine), are capped in jobs, turns, time, tokens, log size, calls and runs per day, never render or approve, pause on a usage limit or a 429, never retry, and never switch backend during a run; the seat child still receives no `keyEnv` variable. No other route may invoke Claude or a text model. The one other model path is `server/generate.mjs`: the Brand tab's Generate button makes one image (Gemini, with 0-3 of the brand's pictures as subject references, e.g. a character's angles from its master picture) or one clip (Gemini Omni, `gemini-omni-1.1-flash` through `/v1beta/interactions`, 720p, with 0-3 of the brand's pictures as subject references; plan `.ai/plans/scene-script.md` part B) per click, as does a scene's Generate clip in New from script (prompt from the brand's `clipBrief`, references from `clipRefs`, the saved name put into that scene's `CLIP:` line; never a batch), and its Refresh models button lists the key's models (metadata only), with the person's own `GEMINI_API_KEY` from the environment, capped by `config/studio.json` → `generate`, saved once into the brand's assets. The Director, `engine/`, prepare, render, a cron or a loop never call it. The third is `server/voice-cloud.mjs` (user decision 2026-10-29): a job's Make cloud voice button (Script tab) sends each missing voice line once to ElevenLabs (`with-timestamps`) with the person's own key (`voiceCloud.keyEnv`, default `ELEVENLABS_API_KEY`, loaded like the other `keyEnv` names), capped by `config/studio.json` → `voiceCloud` (one run at a time, lines per run and per day, characters per day and per line, a pause on 429 or a spent quota, no retry), and saves the audio and word times in `out/<project>/<job>/cloud-voice/`; prepare reads them through `engine/cloudvoice.mjs` (a line not made keeps the local voice and is listed in `timing.cloud.stale`; a cast `speaker` keeps its local voice), and the Director, `engine/`, a cron or a loop never call it. The fourth is `server/assistant-model.mjs` (user decision 2026-10-30): the Assistant panel's composer has a model select (`assistant.models`, `provider:model` refs picked in the Settings tab, "Commands only" turns it off); the parser runs first, and only a plain line it does not know goes once to that model through the API worker's adapters (one `pick_intent` tool call) with the person's own key for that provider (header only, redacted; never the Claude seat) to name one of the panel's intents, capped by `config/studio.json` → `assistant` (`freeform`, `maxAsksPerDay`, one at a time, timeout, byte cap, pause on 429, no retry, log in `logs/assistant/`); the pick goes through the same proposal checks as a typed line and still needs the person's approval.
- The UI server binds to 127.0.0.1 and refuses other hosts and cross-site writes. Do not change that. The one network-facing piece is the read-only review link (`server/review.mjs`, user decision 2026-10-21): started by the person with `npm run ui:review`, one private IPv4, GET/HEAD only on a fixed allowlist (the normal UI with `data-review`, which hides every edit control, plus the reads it needs), a random access code per start. It never runs the Director, Generate or TTS, never shows the Director log, and has no approve, render or any write; keep it that way.

- API providers in `config/providers.json` keep keys in environment variables. The one file allowed to hold a key is the gitignored `.env` at the repo root (user decision, 2026-10-15). `server/keys.mjs` reads it once when the UI server starts, for the `keyEnv` names only, and the environment wins. ## Conventions

- Every label, message, error and status text the tool shows (UI, server responses, CLI output, engine errors, template chrome) is English. The person may talk to Claude in Vietnamese; the product itself stays English. Video copy follows the brand's `voice.lang`, not this rule.

- Engine and server code: Node ESM, no framework, `spawn` with `shell:false` and argument arrays only.
- Every id from outside (project, job, template, file) goes through `assertId` / `assertFileName` + `within()`.
- Text into composition HTML goes through `escapeHtml`; JSON into `<script>` goes through `jsonForScript`.
- A template is deterministic: everything visible is a function of `seek(t)`. No timers, no `Math.random` at render time.

### NEVER (security floor — never work around these; ask instead)
- NEVER invoke Claude or any model from `server/`, the UI, the engine, a cron or a loop — four person-clicked paths only, capped, one at a time, no auto-start, no retries: `server/director.mjs` (Run Director: the Claude seat with `claude.exe -p`, or the API worker in `server/worker/` on the one provider named by `config/providers.json` → `default`, with the person's own key from `keyEnv`) and `server/generate.mjs` (one Gemini image, or one Gemini Omni clip with 0-3 brand pictures as references, into the brand's assets, or one model-list call, `GEMINI_API_KEY` from the environment only, header only, `generativelanguage.googleapis.com` only, the clip's download included) and `server/voice-cloud.mjs` (Make cloud voice on a job: each missing voice line once to ElevenLabs with word times, the person's own key from `config/studio.json` → `voiceCloud.keyEnv`, header only, capped by `voiceCloud`, saved into the job; prepare only reads it) and `server/assistant-model.mjs` (the Assistant panel: with `assistant.freeform` on and a model picked, a line the parser does not know goes once to that connected API provider's model with the person's own key, header only, capped by `assistant`; the model names an intent, the person still approves the card)
